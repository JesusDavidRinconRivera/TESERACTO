 2. SERVICIOS Y APLICACIONES USADOS
================================================================

[A] GITHUB ................. Repositorio de codigo fuente
    - URL: https://github.com/JesusDavidRinconRivera/TESERACTO
    - Rama principal: main
    - Origen remoto: https://github.com/JesusDavidRinconRivera/TESERACTO.git
    - Uso: guardar el codigo; Cloudflare Pages hace deploy automatico

    - Comando de subida:  git add . && git commit -m "mensaje" && git push origin main

[B] CLOUDFLARE ............. Hosting (Pages), DNS y dominio
    - Dashboard: https://dash.cloudflare.com
    - Proyecto Pages: "teseracto"
    - URL de produccion: https://teseracto.pages.dev
    - URL con hash (version exacta): https://<hash>.teseracto.pages.dev
      (se ve en Workers & Pages > teseracto > Deployments)
    - Los nameservers del dominio teseracto.tech apuntan a Cloudflare
      (Spaceship ya NO administra el DNS, solo el registro del dominio)
    - Variables de entorno del proyecto (Settings > Variables and Secrets):
        RESEND_API_KEY = <re_xxxxxxxxxxxxxxxx>  (NO subir la key real a GitHub;
        se obtiene en Resend > API Keys y se pega en Cloudflare. La key real
        vive unicamente en Cloudflare y en Resend, no en el repositorio)
    - IMPORTANTE: el proyecto debe ser tipo PAGES (no Worker).
      Los Workers con "assets estaticos" NO compilan la carpeta functions/.
      Si aparece "Variables cannot be added to a Worker that only has
      static assets" significa que el proyecto quedo como Worker y hay que
      recrearlo como Pages conectado a Git.
    - Como redeployar tras cambios de variables: Deployments > Rerun deployment

[C] RESEND ................. Servicio de envio de correo (API)
    - Dashboard: https://resend.com
    - Dominio verificado: teseracto.tech (status: verified)
    - Region: sa-east-1 (Sao Paulo)
    - Capacidades: sending enabled, receiving disabled
    - Plan: gratuito (100 correos/dia)
    - API base: https://api.resend.com/emails

[D] SPACESHIP .............. Registrar del dominio + correo (Spacemail)

 3. FLUJO DEL FORMULARIO DE CONTACTO
================================================================
Usuario llena formulario "Solicita tu cotizacion" en la web
    -> js/forms/sendForm.js hace POST a /api/contact (fetch)
    -> functions/api/contact.js (Cloudflare Pages Function)
        -> valida campos y correo
        -> lee context.env.RESEND_API_KEY
        -> POST a https://api.resend.com/emails
    -> Resend envia el correo
        -> llega a contacto@teseracto.tech (buzon Spacemail)
    Respuestas HTTP posibles del formulario:
        200 ok   -> correo enviado
        400      -> campos incompletos o correo invalido
        500      -> fallo (incluye resendStatus con el codigo de Resend:
                    401=key invalida, 422=from invalido, 403=sin permiso)

 5. VERSIONADO
================================================================
Formato de version: X.Y.Z
    X = 1 (version principal, fija)
    Y = cantidad de cambios GRANDES
    Z = cantidad de cambios PEQUENOS
Version actual: v1.4.15  (visible en el hero, junto a "Sistemas monitoreados en tiempo real")
Regla: al hacer un cambio nuevo, subir Y o Z y actualizar:
    1. index.html  -> badge de la linea de estado del hero
    2. VERSIONES.txt -> agregar fila con hash, fecha, tipo y version
    3. commit con mensaje descriptivo

    curl https://api.resend.com/domains \
      -H "Authorization: Bearer <RESEND_API_KEY>"

================================================================
 7. RECORDATORIOS IMPORTANTES
================================================================
- El proyecto en Cloudflare DEBE ser Pages (compila functions/).
  Los Workers con static assets NO compilan functions/.
- Los cambios de variables de entorno en Cloudflare Pages requieren
  un Rerun deployment para aplicarse.
- La key de Resend se compartio en un chat: considerar regenerarla.
- El dominio teseracto.tech todavia debe conectarse al proyecto Pages
  en Settings > Custom domains (hasta que eso se haga, la web vive en
  teseracto.pages.dev).
- Spaceship maneja el correo (Spacemail) y el registro del dominio.
  Cloudflare maneja el DNS y el hosting.
- No borrar los registros MX de Spacemail (mx1/mx2.spacemail.com)
  que aun existen junto a los de Resend.
- Resend usa region sa-east-1 (Sao Paulo) para el envio.
